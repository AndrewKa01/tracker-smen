# Трекер смен — локальный запуск

## Первый запуск
```
pip install -r requirements.txt
python app.py
```
Открыть в браузере: http://127.0.0.1:5000

При первом запуске рядом с `app.py` появится файл `database.db` —
это и есть твоя SQLite-база. Дальше просто держишь её вместе с
проектом, ничего руками создавать не нужно.

## Как это устроено
- `app.py` — Flask-сервер: отдаёт `index.html` и статику, плюс два
  эндпоинта `GET/POST /api/state`.
- `database.db` — сама база (три таблицы: `shifts`, `settings`,
  `month_goals`). Появляется автоматически при первом запуске.
- `static/style.css`, `static/script.js` — то же самое, что было в
  едином HTML-файле, просто вынесено в отдельные файлы.

## Важно
Сервер — процесс `python app.py`. Пока он не запущен, страница
скажет «не вижу сервер» и данные не сохранятся. Так что перед тем,
как вносить смену — сначала запускаешь сервер, потом открываешь
страницу.

## Доступ с телефона
Сервер теперь слушает всю локальную сеть (`host="0.0.0.0"`), и пока
`app.py` запущен — в сети рассылается имя `smena.local`, сразу на все
найденные сетевые адаптеры (Wi-Fi, Ethernet, виртуальные — какие есть).
На телефоне, подключённом к тому же Wi-Fi, что и ПК, открой:
```
http://smena.local:5000
```
Если не резолвится — в консоли, где запущен `app.py`, при старте
печатается строка вида:
```
[mDNS] smena.local -> 192.168.1.42, 172.x.x.x, ...
```
Это все IP-адреса, которые нашлись на компьютере. Один из них — твой
настоящий Wi-Fi-адрес (обычно `192.168.x.x`), остальные могут быть
виртуальными (VPN, WSL, Docker, Hyper-V) — до них с телефона всё равно
не достучаться, это нормально. Рабочий запасной вариант — открыть
`http://<настоящий IP>:5000` напрямую, без `smena.local`.

Как только останавливаешь `app.py` (Ctrl+C) — и `smena.local`, и IP
перестают отвечать, это ожидаемо: без запущенного сервера отвечать
нечему.
